# M1 · Auth + Session Gate — Plan

**Milestone:** M1 (Onboarding + First Rep) — the auth slice.
**Branch:** `feat/m1-auth`
**Date:** 2026-07-26
**Status when written:** design approved by founder (Supabase, magic-link email); founder at gym, autonomous build authorized.

## Goal

Gate the app behind a real account. Sign in with **Apple**, **Google**, and **email (magic link)**;
issue and persist a session; attach that session to the coach proxy so `POST /coach` only serves
authenticated users. This is the security half of M1 and the fix for the M3 `/review` finding
"no auth check on `POST /coach`".

## Decisions (locked)

- **Provider matrix (minimize native deps + founder setup):**
  - **Apple** — native `AuthenticationServices` (`ASAuthorizationController`), identity token handed to
    Supabase via `signInWithIdToken(provider: .apple)`. No SPM package; needs the *Sign in with Apple*
    capability + Supabase Apple provider.
  - **Google** — Supabase OAuth web flow (`signInWithOAuth(provider: .google)` over
    `ASWebAuthenticationSession`). **No GoogleSignIn SPM package.** Needs Supabase Google provider config.
  - **Email** — Supabase magic link (`signInWithOTP`, `shouldCreateUser: true`). No passwords anywhere.
- **The only new SPM package is `supabase-swift`.** It is imported by exactly one file
  (`SupabaseAuthService.swift`), guarded by `#if canImport(Supabase)`, so the app builds green with or
  without package resolution. A factory picks the Supabase impl when the module is present, else a
  clearly-surfaced `UnconfiguredAuthService`.
- **Session storage:** the Supabase SDK persists the session (Keychain) — we do **not** hand-roll token
  storage. `AuthController` mirrors the current session into memory for the UI + token provider.
- **Proxy gate:** `POST /coach` requires a valid `Authorization: Bearer <supabase-jwt>`. Verified locally
  with `jose` HS256 against `SUPABASE_JWT_SECRET` (fast, unit-testable, no per-request round-trip).
  **Fail-closed:** secret unset → `503`; missing/invalid/expired token → `401`. (If the founder's project
  uses asymmetric JWTs, swap to `createRemoteJWKSet` — one-line change, noted in `proxy/README.md`.)
- **Redirect:** reuse the `yap://` scheme → `yap://auth-callback`. `YapApp.onOpenURL` forwards
  auth-callback URLs to `AuthController.handle(url:)`.
- **Profile:** `ProfileRepository` protocol; `LocalProfileRepository` (@AppStorage — already satisfies the
  M1 DoD "persists across relaunch"). A `#if canImport(Supabase)` `SupabaseProfileRepository` best-effort
  upserts to a `profiles` row when signed in (survives reinstall). Onboarding writes goal/interests/format
  through the repository. Server sync is a bonus, not on the DoD critical path.

## Architecture

All Swift auth code under `Yap/Auth/`. Pure/logic pieces (protocol, domain types, controller state
machine, mock) are SDK-free and unit-tested. The SDK adapter is the only Supabase-touching file.

```
Yap/Auth/
  AuthModels.swift          # AuthUser, AuthSession, AuthProvider, AuthError, AuthPhase
  AuthService.swift         # protocol: signInApple/Google/email(OTP), handle(url:), signOut, currentSession, sessionStream
  MockAuthService.swift     # deterministic test/preview double
  UnconfiguredAuthService.swift # surfaces "auth not configured" when the SDK/creds are absent
  AuthController.swift       # @Observable @MainActor; phase, current user, error; wraps a service
  AuthGate.swift            # functional gate view (logic-first); provider buttons + email field + magic-link "check your inbox"
  SupabaseAuthService.swift  # #if canImport(Supabase) — the ONLY file importing Supabase
Yap/Data/
  ProfileRepository.swift    # protocol + UserProfile + LocalProfileRepository
  SupabaseProfileRepository.swift # #if canImport(Supabase)
Yap/Config/
  YapConfig.swift            # Supabase URL + anon key (Info.plist, dev override) + proxyURL (moved from CoachRunner)
```

**Flow:** `RootView` → `AuthGate` (no session) → provider sign-in → session → `OnboardingView`
(if not onboarded) → `MainTabView`. `RecordFlow` reads `authController.accessToken` and passes it to
`CoachRunner.run(...)` → `HTTPCoachBackend`, which attaches the Bearer header. Proxy verifies → Claude.

## Tasks (TDD, commit per task)

- **A. Domain types + `AuthService` protocol + `MockAuthService`.** `AuthPhase` (`.signedOut`,
  `.authenticating`, `.signedIn(AuthUser)`, `.failed(AuthError)`), `AuthProvider` (`.apple`, `.google`,
  `.email`). Mock drives scripted outcomes. *Tests:* mock returns session; error path; email→awaiting-link phase.
- **B. `AuthController`.** `@MainActor @Observable`; `signIn(with:)`, `submitEmail(_:)`, `handle(url:)`,
  `signOut()`; publishes `phase`, `currentUser`, `accessToken`, `errorMessage`. *Tests:* transitions via mock,
  including magic-link-sent and callback-completes.
- **C. `YapConfig` + Bearer wiring.** Move `proxyURL` read out of `CoachRunner` into `YapConfig`; add
  `supabaseURL`/`supabaseAnonKey` (Info.plist keys, empty default, dev `UserDefaults` override). Add
  `accessToken: () async -> String?` to `HTTPCoachBackend`; thread token param through `CoachRunner.run`;
  `RecordFlow` supplies it from the controller. *Tests:* header present when token non-nil, absent when nil
  (via a stub `URLProtocol`).
- **D. Proxy JWT gate.** `verifyBearer(req)` using `jose` HS256 + `SUPABASE_JWT_SECRET`; fail-closed. Wire
  into `POST /coach`. *Tests (node):* valid, expired, wrong-secret, missing header, malformed, secret-unset→503.
- **E. `ProfileRepository` + local impl + onboarding wiring.** *Tests:* round-trip goal/interests/format.
- **F. Supabase adapters (guarded) + `project.yml`.** `SupabaseAuthService` + `SupabaseProfileRepository`
  behind `#if canImport(Supabase)`. Add `supabase-swift` to `project.yml packages` + app `dependencies`;
  `xcodegen` + resolve. **If resolution fails in this environment, back the package out of `project.yml`,
  re-gen, and leave the guarded files (they compile to nothing) — build stays green, founder adds the
  package on return.**
- **G. Apple entitlement + `AuthGate` gate wiring + `RootView`.** Add `com.apple.developer.applesignin` to
  `Yap.entitlements` + `project.yml`. `RootView` shows `AuthGate` until signed in.
- **H. Build + full test suite + `/review` + PR.** `xcodebuild test` (iPhone 17 sim) green; `proxy` tests
  green. Update ROADMAP progress log. Push, open PR, `/review`, address findings. **Do not merge** —
  DoD requires founder credentials + a real-device sign-in pass.

## Out of scope (YAGNI for M1)

Native GoogleSignIn account-picker (web OAuth is fine now; easy upgrade later), provider account linking/
merging, MFA, account deletion UI, password auth (magic-link only), server-side sync of `YapRecord` history.

## Definition of Done (this slice)

- [ ] App launches to `AuthGate`; unauthenticated users cannot reach the loop.
- [ ] Apple / Google / email(magic-link) each yield a persisted Supabase session (relaunch stays signed in).
      *(manual, device + founder creds — cannot be unit-verified)*
- [ ] `POST /coach` returns 401 without a valid token, 200 with one; secret-unset → 503. *(node tests)*
- [ ] `HTTPCoachBackend` attaches the Bearer token; no key or secret ships in the client. *(unit tests)*
- [ ] Profile (goal/interests/format) persists across relaunch. *(unit tests + local)*
- [ ] All existing tests still green; new unit tests green. *(evidence in progress log)*

## Founder credential-drop (for return) — see `docs/AUTH_SETUP.md`

1. Create a Supabase project → copy **Project URL** + **anon key** → set in `YapConfig` (Info.plist /
   `Secrets.xcconfig`). Copy the **JWT secret** → `proxy/.env` `SUPABASE_JWT_SECRET`.
2. Supabase → Auth → Providers: enable **Apple** (Services ID + key) and **Google** (client id/secret).
   Add redirect URL `yap://auth-callback`.
3. Xcode/Apple Developer: enable the **Sign in with Apple** capability for `com.yap.app`.
4. (When the proxy is deployed) set `yap.proxyURL`; rotate the pasted Anthropic key first.
